1. Arquitectura y Stack Tecnológico

  • Go (Golang): Seleccionado por su eficiencia en concurrencia (goroutines) para manejar picos transaccionales sin agotar hilos del sistema, garantizando latencias menores a 2 segundos.
  • PostgreSQL: Base de datos relacional robusta que garantiza el cumplimiento ACID. Utiliza bloqueos a nivel de fila (SELECT ... FOR UPDATE) para prevenir condiciones de carrera.
  • IA Asíncrona: La evaluación de riesgo se ejecuta en un proceso no bloqueante, evitando penalizar el tiempo de respuesta.

2. Sincronización y Protección del Core

  • El problema: El core legado Bancs se degrada ante altas ráfagas de consultas directas (10 000 TPS).
  • La solución (Patrón Outbox): El microservicio asume la carga inmediata. Los saldos se sincronizan hacia Bancs de forma asíncrona mediante un consumidor con limitación de tasa.
  • Beneficio: Garantiza la resiliencia del sistema heredado procesando las actualizaciones a un ritmo predecible y controlado.

3. Incidente de Operaciones: Deadlocks

  • Síntomas: Latencia severa y errores de timeout reportados durante el pico de quincena.
  • Mitigación Inmediata: Identificación y terminación forzada (kill) de las conexiones bloqueantes en la base de datos para restablecer el flujo.
  • Estabilización: Aplicación de limitación de tasa a nivel de red para reducir la concurrencia masiva.
Observabilidad: El uso de Correlation IDs inyectados en los logs permite trazar la transacción afectada e identificar la latencia en la capa de datos.

4. Calidad de Datos (Pipeline ETL)

  • Objetivo: Preparar los registros históricos del sistema Bancs para el modelo de IA.
  • Transformación: El script en Python realiza la limpieza de valores nulos y estandariza formatos.
  • Impacto: Mitiga el Data Drift estableciendo una estructura JSON limpia, fundamental para el monitoreo y el reentrenamiento del modelo predictivo.
